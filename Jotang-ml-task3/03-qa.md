# Task3 趁热打铁六问

## 1. 前向传播为什么要保存每一层的输入或输出？反向传播会在哪里用到它们？这和显存有什么关系？

反向传播求梯度依赖链式法则，而链式法则的每一项都要用"当时前向的值"才能算：算本层权重的梯度要用本层前向时的输入（比如 dW2 = A1ᵀ@dZ2 里就用了 A1），算激活函数的局部导数要用激活前的 Z1（ReLU 的 (Z1>0) 就是它）。所以反向传播在每一层计算权重、偏置的梯度时，都要取用前向保存下来的中间值。这些中间值从算出来那一刻起就得一直留着，等反向经过时再取——这就是训练比推理吃显存的原因：显存里存的不只是参数，还有这一大堆中间激活值。

## 2. 链式法则怎样把损失函数的梯度传回第一层权重？请结合自己的计算图说明

链式法则的核心是复合函数求导：

$$\frac{\partial L}{\partial w_1}=\frac{\partial L}{\partial y_n}\cdot\frac{\partial y_n}{\partial y_{n-1}}\cdots\frac{\partial y_2}{\partial y_1}\cdot\frac{\partial y_1}{\partial w_1}$$

以实践 2 的网络为例，前向计算图：

```
X ──► Z1 = X@W1+b1 ──► A1 = ReLU(Z1) ──► Z2 = A1@W2+b2 ──► P = σ(Z2) ──► L
  └─(W1, b1)─┘            └─(W2, b2)─┘
```

反向从终点 L 出发，从后往前：先算 ∂L/∂Z2 = P − y（sigmoid 和 BCE 融合后的结果），再 ∂L/∂A1 = dZ2@W2ᵀ，∂L/∂Z1 = dA1⊙(Z1>0)，最后 ∂L/∂W1 = Xᵀ@dZ1。每一层都把上游传过来的梯度乘上本层的局部导数，一路乘回最开始的权重——连乘公式就这样拆成了一串"每次只乘一小步"。

## 3. 二元交叉熵与 Sigmoid 配合后，loss 对 logit 的梯度是什么？这个结果为什么方便反向传播？

设 ŷ = σ(z)，z 就是 logit，二元交叉熵：

$$L = -\left[y\log\sigma(z) + (1-y)\log\bigl(1-\sigma(z)\bigr)\right]$$

求导结果：

$$\frac{\partial L}{\partial z} = \sigma(z) - y = \hat{y} - y$$

这个形式非常简洁：反向传到 logit 这一层时，梯度就是"预测值减标签"，不需要单独算 sigmoid 的导数，计算量小，数值也更稳定。

## 4. NumPy 梯度与 PyTorch 梯度出现差异时，你会怎样判断问题出在公式、矩阵转置、广播还是损失的求平均方式？

按嫌疑大小依次排查：

1. **损失的求平均方式**：NumPy 手写梯度最容易在这里出问题——忘了 loss 是对 batch 求平均，反向时忘了除 n，或者该求和的求成了均值；
2. **矩阵转置**：矩阵乘法维度很容易不匹配，X@W 和 W@X 搞反、该转置的没转置；
3. **广播机制**：NumPy 和 PyTorch 的广播规则大致一样，但维度不一致时广播出来的结果可能不同，重点看标签、偏置这类形状不一样的量有没有触发意外广播；
4. 最后才核对求导公式本身有没有写错。

排查技巧：先只用单个样本测试，把广播和平均的干扰都消掉，单样本梯度对齐了再加大 batch——差异一回来，就知道问题出在这两处里的哪一处。

## 5. 完成两次验证后，你现在怎样理解 loss.backward()？它替我们保存和完成了哪些工作？

loss.backward() 是 PyTorch 自动微分的入口，负责启动反向传播、自动完成链式求导。它做的事：

1. 读取前向时构建好的计算图和保存下来的中间激活值（前向计算的时候图就记好了，每个运算都连在图上）；
2. 从 loss 节点出发，沿计算图反向遍历，链式法则逐层求导，算出所有 requires_grad=True 张量的梯度；
3. 把算好的梯度写进每个张量的 .grad 属性，之后优化器读 .grad 就能更新权重。

对照这两次实验：我手推公式、手写反向、再和它逐项对数字——它做的正是我手写的那一套，只是不用我操心公式推导和形状变换。

## 6. 将你遇到的报错或不理解的点记录

1. `RuntimeError: grad can be implicitly created only for scalar outputs`：backward() 默认要求 loss 是标量；如果输出是向量，要传入 grad_tensor，比如 backward(torch.ones_like(output))；
2. 梯度消失：深层网络反向时连续乘小于 1 的导数，越往前梯度越小，靠前的权重几乎不更新；
3. 梯度爆炸：反过来梯度越乘越大，权重更新震荡不收敛；
4. 忘记 optimizer.zero_grad()：PyTorch 的梯度是累加的，不清零就会把上一轮的梯度混进来，训练跑偏。
