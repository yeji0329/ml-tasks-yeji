# Task3 拓展：用 NumPy 反向传播训练 make_moons

把实践 2 的手写反向传播接上完整训练循环，替换掉 Task1 里 loss.backward() 自动求的梯度，在 make_moons 上做全量（batch）梯度下降。与 Task1 保持同数据（n=1000、noise=0.2、seed=42，600/200/200 划分）、同结构（2→16→8→1）、同损失（BCEWithLogits 数学等价形式），唯一的变量是梯度来源和优化器：Task1 用 autograd + Adam，这里用手写反向 + 朴素全量 GD。

实验内容：先扫了一组学习率（0.05 / 0.2 / 0.5 / 1.0 / 2.0）各跑 1000 epoch，选出最优后正式训练，画学习曲线和决策边界，最后把手写梯度对 autograd 做了一次全量复核（六组参数最大误差 1e-17 量级，确认反向实现无误）。

## 三个观察点

### 1. 能否正常收敛？

能。lr=0.5 时前 100 epoch val acc 就到 0.91，200 epoch 到 0.96，之后缓慢爬升，1000 epoch 收在 0.9750。全量梯度下降方向稳定（每步都是全数据的真梯度），不需要 Adam 那样的自适应步长也能顺利收敛，学习率成了唯一要调的旋钮。

### 2. 对比 Task1 的模型表现

数字上反超了：test acc 0.9900 vs Task1 Adam 的 0.9850（val acc 0.9750 vs 0.9400）。但这不是"手写反向比框架好"——两者梯度在 1e-17 量级上一致，真正的差别在优化路径：全量 GD 每步走确定的真梯度，大方向不摇摆；Task1 的小批量 + Adam 每步带采样噪声。在这个只有 600 样本、边界平滑的小任务上，稳稳的大步走反而占优。学习率扫描也印证了步长的作用：0.5 和 1.0 并列最高（0.9750），2.0 反而掉到 0.9650——太大后期在最优点附近震荡。

### 3. 决策边界对比

两个模型的边界大形状一致，双月牙的分界都学对了，但精细程度不同：全量 GD 版的边界折角、锯齿更明显，Task1 的 Adam 版更平滑圆润。原因和上面一样——全量 GD 用固定大步长走完 1000 步，边界细节来不及精修；Adam 后期步长自动缩小，在边界附近做了更多微调。可见优化器影响的不只是收敛速度和精度，还有决策面的精细程度。
